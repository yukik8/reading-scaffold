# reading-scaffold

補助が自動で減っていく読書用のChrome拡張(作業リポジトリ / 製品名は未定)。

読む力を意志力ではなく環境で支えて、その支え(ヒント・演出)を本人が気づかない速度で減らしていく。
効果は **「補助なし読書時間」** ひとつで測る。伸びなければ機構の失敗と判定する。

- 設計: [docs/design-doc-v0.md](docs/design-doc-v0.md)
- ステータス: v0 / W1(計測)・W2(演出+LLMクイズ)・W3(連続θの自動漸減+ホメオスタット)実装済み — ドッグフーディング中

## 原則(コードで守るもの)

1. **ページを改変しない。** 追加するのはShadow DOM内のオーバーレイのみ。広告除去・本文再構成・ペイウォール回避は行わない。
2. **計測はセッション中のみ。** タブ観測の全ハンドラは最初にセッションの存在を確認し、無ければ何も読まず何も書かずに戻る(MV3はService Worker再起動で動的リスナーが消えるため、登録/解除方式ではなく常設+ガード方式で守る。判断の詳細は [session.js](extension/src/background/session.js) 冒頭)。
3. **θの目標値は常に0。** エンゲージメント指標を制御器の入力にしない(スロットマシン化の構造的禁止)。
4. **生データはローカルのみ。** 生イベントはIndexedDBに留め、サーバへ出すのは週次の派生指標だけ。離脱先はドメイン文字列のみ、URL全体とタイトルは保存しない。

## 構成

```
extension/          Chrome拡張(MV3・ビルド不要のESモジュール)
  manifest.json
  src/background/   Service Worker: セッション状態機械 / 制御器 / IndexedDB
  src/content/      セッション中だけ注入されるcontent script(可視段落の計測・オーバーレイ)
  src/popup/        診断・Mirror・データ削除
  src/shared/       θテーブル等の設定、イベント型
docs/               設計ドキュメント
server/             FastAPI(v0後半・/hint と /metrics)
```

ビルド工程は意図的に置いていない。`chrome://extensions` → デベロッパーモード → 「パッケージ化されていない拡張機能を読み込む」で `extension/` を選べばそのまま動く。TypeScript化が必要になった時点で入れる。

## マイルストーン

| 週 | 作るもの | 完了条件 |
|---|---|---|
| W1 | 計測だけの拡張(ボタン→セッション→dwell計測→ローカルMirror) | 自分の読書のベースラインが数字で見える |
| W2 | オーバーレイ(定型ヒント+お祝い+θ手動ダイヤル) | θを変えると読書体験が変わる |
| W3 | 制御器接続(連続θの自動漸減+不変条件) | 1週間放置してθが自動で動く |
| W4〜 | LLMヒント+診断+磨き | ドッグフーディング本番 |

W1が最重要。演出とLLMが遅れてもW1の計測データは11月中間発表の素材になる。
