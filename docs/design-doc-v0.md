# Design Doc: ドーパミン補助輪付き読書拡張 v0

- **Author:** 祐希
- **Status:** Draft(2026-08-16)
- **Audience:** 実装者(本人+AI)
- **Context:** PRDのMVP(v0)の実装方針。製品の Why/What はPRDに委ね、本書は How のみを扱う。PRDとプロジェクト全体の文脈は本リポジトリ外(手元の `cognitive-exoskelton/`)にある。

---

## 1. Design Goals / Non-Goals

### Goals
- 11月中間発表までに、開発者自身のドッグフーディングで「補助なし読書時間」の推移データを取れる状態にする
- 計測(センサー)を最優先で堅くする — 制御と演出は計測の上に載る
- 「計測はセッション中のみ」を約束ではなく**権限モデルとコード構造で強制**する

### Non-Goals
- 機械学習・パラメータの自動最適化(v0はルールベース。学習はβのデータが集まってから)
- Chrome以外のブラウザ対応、モバイル
- アカウント・サーバ側のユーザーデータ保存(v0はローカルのみ+匿名の派生指標)

## 2. System Overview

```
┌─ Content Script(各タブ・セッション中のみ注入) ─┐
│  本文検出(Readability, 読取専用)               │
│  オーバーレイUI(演出・ヒントカード・進捗)        │
│  計測(可視段落・スクロール・操作)               │
└──────────────┬──────────────────────────────┘
               │ chrome.runtime messaging
┌──────────────▼──────────────────────────────┐
│  Service Worker(MV3)                         │
│  セッション状態機械 / タペリング制御器           │
│  イベントログ書き込み(IndexedDB)               │
│  タブ離脱の観測(tabs API, セッション中のみ)      │
└──────┬───────────────────────┬──────────────┘
┌──────▼──────────┐   ┌───────▼──────────────┐
│ Popup / 設定UI    │   │ FastAPI(サーバ)       │
│ 診断・Mirror・削除 │   │ LLM中継・派生指標受信   │
└─────────────────┘   └──────────────────────┘
```

- データは**ローカルファースト**: 生イベントはIndexedDBのみ。サーバへは週次集計値(派生指標)だけを送る
- LLMはv0後半まで不使用(ヒントは定型文で機構を検証する)

## 3. セッションモデル

### 状態機械

```
IDLE ──[読むボタン押下]──> ACTIVE
ACTIVE ──[離脱: タブ切替/ウィンドウ非フォーカス]──> ESCAPED
ESCAPED ──[復帰]──> ACTIVE
ACTIVE ──[終了ボタン / タブclose]──> ENDED
ACTIVE ──[無操作 3分]──> ENDED(auto)
ESCAPED ──[復帰なし 3分]──> ENDED(auto)
```

- **開始は必ずユーザージェスチャー**(拡張アイコンまたはページ内ボタン)。これがactiveTab権限の発動条件を兼ねる
- 離脱はセッションを**終わらせない**(離脱→復帰のパターンが制御器の主要シグナルのため)。復帰しないまま3分で自動終了
- 「読書時間」の操作的定義: **本文段落がIntersectionObserverで可視、かつ直近30秒以内にスクロールまたは操作がある時間**(30秒粒度のdwell tickで積算)

### 権限戦略

| 権限 | 用途 | 要求タイミング |
|---|---|---|
| `activeTab` + `scripting` | 読むボタンを押したタブへの注入 | ジェスチャー時のみ(常時`<all_urls>`を要求しない) |
| `tabs` | 離脱先のドメイン観測(セッション中のみリスナー登録) | インストール時 |
| `storage` / IndexedDB | イベントログ・設定 | インストール時 |

- 「セッション中のみ計測」は、**リスナーをセッション開始時に登録し終了時に解除する**ことで構造的に保証する。離脱先はドメイン文字列のみ保存(URL全体・タイトルは保存しない)

## 4. データ設計(IndexedDB)

### events(append-only)

```
{ id, session_id, t(epoch ms), type, payload }
type ∈ {
  session_start   { url_domain, article_len_words, level, theta }
  dwell_tick      { visible_paragraph_range }        // 30秒毎
  scroll          { depth_pct }
  tab_escape      { to_domain }
  tab_return      { away_ms }
  hint_shown      { hint_id, kind }                  // kind: canned | llm
  hint_clicked    { hint_id }
  effect_shown    { effect_id }
  session_end     { reason: manual|close|idle, read_ms, completion_pct }
}
```

### sessions(集計キャッシュ)

```
{ session_id, date, domain, level, theta, read_ms, escapes, completion_pct, success(bool) }
success := read_ms >= 5分 かつ escapes <= 1
```

### state(単一レコード)

```
{ level, theta, success_streak, fail_streak, diag_answers, updated_at }
```

### 派生指標(週次でサーバ送信・匿名)

```
{ week, unassisted_read_min, assisted_read_min, sessions, escape_rate, level }
```

## 5. タペリング制御器 v0(2026-08-16改訂: 連続θ)

> **改訂の理由:** 初版はθの離散5段階(Level 0〜5)だったが、段差(例: 8→5は37%減)は
> 本人が気づき得る。テーゼは「気づかれない速度で減らす」なので、θを連続値にし、
> Weber-Fechnerの法則(気づける最小変化=JNDは現在量の約10〜20%)に基づき
> **JND未満の乗算的漸減**にする。「Level」は制御から廃止(表示用の節目=帯としてのみ導出可)。

- **操作量(1つだけ):** θ ∈ [0, 8] の連続値 = ヒント・演出の頻度(本文1,000語あたり)
- **方策:**

```
セッション終了ごとに:
  if success: success_streak += 1; fail_streak = 0
  else:       fail_streak += 1;    success_streak = 0

  if success:                 θ ← θ × (1 − α)    # α=0.10(JND未満。本人に通知しない)
  if fail_streak >= L:        θ ← θ × (1 + β)    # β=0.30, L=2(戻すときは大きめ=ヒステリシス)
  if θ < 0.3:                 θ ← 0              # 乗算は0に到達しないため、ここでスナップ=卒業
```

- **迷彩(トレンド隠蔽):** セッションごとの実効θ = θ × (1±0.1の乱数)。
  日々±10%揺れる中を成功あたり平均10%下るので、下降トレンドがノイズに埋もれる
- **不変条件(コードで強制):**
  - θの目標値は常に0(エンゲージメント指標を制御器の入力にしない。クイズ正誤も入れない)
  - 1日の総変化は±15%まで(急激な変化の禁止)
  - 卒業(θ=0)後は監視のみ。`unassisted_read_min`の4週移動平均が50%以上低下したときだけ一時的にθを再展開し、回復したら再び0へ(ホメオスタットモード)
- α, β, ノイズ幅は設定ファイルに置き、ドッグフーディング中は手動でも調整可能にする(θ直接ダイヤル)

## 6. オーバーレイとMicro Content

- **描画:** Shadow DOM内に構築(ページのCSSと相互汚染しない)。ページDOMへの変更は行わない — オーバーレイ要素の追加のみ
- **ヒントの種類(v0):**
  1. 定型文ヒント(canned): 進捗の相槌・区切りの声かけ。テンプレート+乱数タイミング(θに従う)
  2. 読了お祝い(effect): セッション成功時のみ
  3. (v0後半)LLMヒント: 可視段落のテキストを渡し、一行の理解フック(「この段落、冒頭の主張の根拠になってる」)を生成。**キャッシュ必須・1セッションの生成回数上限をθと連動**
- **禁止事項:** ヒントから外部リンクへ誘導しない。オーバーレイは読書から連れ出さない(「連れ出さない刺激」だけが許される)

## 7. 診断とMirror

- **初回診断(Popup):** 5問(1日のショート動画時間 / 最後に本を読み切った時期 / 平均継続時間 / 離脱の自覚 / 読みたい対象)→ 初期Level決定。判定はルックアップテーブル
- **Mirror(Popup内 1画面):**
  - 主表示: **補助なし読書時間(週次推移の棒グラフ)** = Level 4以上のセッションのread_msの合計
  - 副表示: 現在Level(署名リング)、今週のセッション数、離脱率
  - 出さないもの: 連続日数、他人との比較、目標未達の警告(責めない原則)
- **データ削除:** 設定から1タップでIndexedDB全消去+サーバ送信停止

## 8. バックエンド(FastAPI・v0後半)

- `/hint` : {paragraph_text, article_context} → 一行ヒント。APIキーはサーバのみ保持
- `/metrics` : 週次派生指標の受信(匿名ID)。生ログ・本文は受け取らない
- v0前半はバックエンドなしで完結する(定型文ヒント+ローカル集計)

## 9. マイルストーン(歩く骨格)

| 週 | 作るもの | 完了条件 |
|---|---|---|
| W1 | 計測だけの拡張: ボタン→セッション→dwell計測→ローカルMirror | 自分の読書のベースラインが数字で見える |
| W2 | オーバーレイ: 定型ヒント+お祝い+θ手動ダイヤル | θを変えると読書体験が変わる |
| W3 | 制御器接続: 自動昇降+不変条件 | 1週間放置してLevelが自動で動く |
| W4〜 | LLMヒント+診断+磨き | ドッグフーディング本番開始 |

W1が最重要(計測が全ての土台)。演出・LLMが遅れてもW1の計測データは11月発表の素材になる。

## 10. Open Questions(設計レベル)

1. **`tabs`権限の審査リスク:** 離脱先ドメイン観測が審査で問題になった場合の縮退案 = 「離脱した事実と時間のみ記録(行き先なし)」で制御器は成立するか
2. **読了率の定義:** completion_pct = 最深可視段落 / 全段落 でよいか(飛ばし読みと精読の区別はv0では捨てる)
3. **ヒントのタイミング:** 乱数(予測不能性=報酬効果)と、段落境界(理解連動)のどちらを優先するか。v0は「段落境界の候補点から乱数で選ぶ」折衷案で開始
4. **SPA・無限スクロールページの本文検出:** Readabilityが失敗するページの扱い(v0: 検出失敗時は「このページでは補助なしで計測のみ」と表示)
5. **複数記事の連続読書:** 1セッション=1記事とするか、跨ぎを許すか(v0: 1記事。タブ内遷移で新セッション提案)
