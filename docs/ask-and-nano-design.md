# 設計ノート: 「問い」機能とGemini Nano基盤(2026-09-07・提案)

ユーザー発案: ①自分からも質問できるようにして、それが興味や集中の指数に入る
②ChromeビルトインのGemini Nano(Prompt API)でクイズと質問を実装する。
本ノートはその設計案。実装前の合意用。

## 1. 位置づけ: 「問い」は第三のカテゴリ「道具」

reward-design.mdの二分法(演出/記録)に第三カテゴリを追加する:

| | 演出(stimulus) | 記録(record) | **道具(tool)** |
|---|---|---|---|
| 例 | 星・金の雨・クイズ | 帯・読書メモリ | **自分からの問い** |
| 起点 | システム(θ+乱数) | — | **本人** |
| 寿命 | θ配下。卒業で消える | 永続 | **永続。卒業後も使ってよい** |
| 可変報酬 | あり | 禁止 | **禁止(回答に演出をつけない)** |

根拠: 旧PRD FR5「卒業とは刺激の起点が自分になること。Level 5はAIを使ってよい、
ただし自分の問いを起点に呼び出す」。自分からの質問は卒業状態の行動そのものなので、
θ配下に置かない(漸減させない)し、報酬もつけない。
**報酬をつけない理由**: 回答に演出をつけると質問がレバー(スロットの変種)になり、
「興味の指標」も自家汚染される。回答自体が情報報酬(Bromberg-Martin & Hikosaka)。

### 補助輪構造としての「問いの種」との関係

- 問いの種(reward.md P5・未実装): **システム起点**の問い。θ配下で漸減する「問い方の手本」
- 本機能: **本人起点**の問い。永続
- つまり「システムの問いが減るにつれ、自分の問いが増える」が理想の軌跡 —
  補助輪の思想そのもの。両者は同じ生成基盤(Nano)を共有する

## 2. 「問い」のUXと原則

- **入口(2026-09-07決定)**: 常設。ただし邪魔にならない — 右下の小さな半透明リング
  ボタン(FAB)で、クリックすると入力欄が開く。テキスト選択中なら選択部を文脈に含める
- **1問1答**: 会話は続かない(連れ出さない原則)。追い質問はもう一度選択から
- **回答の原則「照らす、答えない」**:
  - 短く答え、根拠になる**読了済み段落を光の枠で指す**(source-glow再利用)
  - 先回りの要約・未読部分のネタバレを禁止(文脈には読了済み段落だけを渡す)
  - 要約アプリ化(読む行為の省略)はNon-Goalの侵犯。回答は常に「本文へ戻す」方向
- **言葉の原則との整合**: 禁止しているのは頼まれていない褒め・教えの押しつけ。
  本人が問うたことに答えるのは「教えない」違反ではない(呼び出し式)

## 3. 計測: 「興味の指数」の入れ方

- **制御器には入れない**(不変条件: 入力はread_ms/escapesのみ)。
  質問数を制御器に入れると「質問すればθが動く」自己目的化回路ができる
- **記録層に questions ストアを新設**(DB v3):
  `{ question_id, page_id, session_id, selection_hash, question, answer, t }`
  = 読書メモリの資産。「何を読んで何を問うたか」は本人だけの複製不能な地図
- **events に question_asked を追加**(計測層。文面は入れない — 層の分離を守る)
- **表示**: ダッシュボードに「自分から問うた数」を事実として表示(責めない・煽らない)。
  帯(θ由来)とは別軸の「問いの自立」として、卒業の質的確認の研究材料にする
- KPI副次指標への昇格はβで妥当性を見てから(v0は記録どまり)

## 4. Gemini Nano(Prompt API)基盤

確認済み(2026-09): 拡張機能で正式サポート / `LanguageModel.availability()` /
構造化出力(JSON Schema, Chrome 137+) / 入出力言語に ja 指定可 / オンデバイス・無料。

- **クイズ生成を移行**: 現行のローカルFastAPI(/quiz)→ SW内のLanguageModelセッション。
  JSON Schemaで {question, choices[3], answer_index} を強制
- **質問応答も同基盤**: 選択テキスト+読了済み段落(上限あり)を文脈に
- **3段フォールバック**: Nano利用可 → ローカルサーバ(現行) → 静かに出さない
- **効果**:
  1. 本文がデバイス外に出る唯一の経路が消える — 「生データはローカルのみ」が完全になる
     (プライバシー物語の完成。ストア審査・β配布にも有利)
  2. サーバ運用が不要になり、クイズが安定する(KPIの理解ガードレールの信頼性)
  3. 無料 — Open Question「LLMコストとβ規模」が消える
- **リスク**: モデルDL要件(ディスク・GPU/RAM)で使えない環境がある / nano級の
  日本語クイズ品質は未知 / 難易度統制はさらに難しくなる → スパイクで判定
